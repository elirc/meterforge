**Proving they bite.**
- Test 1: delete `.UseCollation("Latin1_General_100_BIN2")`, `dotnet ef migrations add CaseInsensitive`, rerun → the second ingest returns `IsReplay = true` (the fixture migrates a fresh database per class). This is exactly incident 004.
- Test 2: it's hard to break through the domain because `UsageEvent` calls `ToUniversalTime()`. Break it by mapping `OccurredAt` as `datetime2` with a value converter that stores `.DateTime` (local wall time, offset dropped): the event is stored as 02:00 and falls outside [00:00, 01:00).

**Why EF InMemory lies here.** The InMemory provider compares strings with .NET ordinal equality (always case-sensitive) and ignores collations, so test 1 passes even when SQL Server would merge the keys. It doesn't use SQL types, so column types, precision and offset handling never run. And it has no unique indexes, so the 2601/2627 path is dead code. SQLite has its own rules (NOCASE only if declared, no `datetimeoffset`). Only the real engine tests the real contract.

**Explain-before-touching.**
1. `.UseCollation("Latin1_General_100_BIN2")` on `ExternalEventId`. Under `SQL_Latin1_General_CP1_CI_AS`, `'evt_aB3' = 'evt_Ab3'` is **true** (CI = case-insensitive, AS = accent-sensitive), and the unique index treats them as duplicates.
2. `datetimeoffset` stores local time + offset; comparisons and index ordering use the UTC instant, so `02:00+02:00 = 00:00+00:00`. Postgres `timestamptz` stores only the UTC instant and drops the offset.
3. The same `external_event_id` in the same tenant would make the second test's ingest a replay of the first test's event. Use unique ids or tenants per test (as the existing tests do).
4. A passing test claims coverage you don't have; a skipped test is visible in the test report, so the gap is honest.
